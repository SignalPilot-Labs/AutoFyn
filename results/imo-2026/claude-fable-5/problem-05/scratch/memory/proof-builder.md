# proof-builder — per-role rules

ALWAYS: Before mechanically following an outline's gap-closing recipe, re-derive the bound yourself — the outline's route may be lossier than necessary (imo-2026-05: outline's GAP 1 needed t²/(4m)+t³/(16m²) via √m constants; the (A)-step division already gave p−q ≤ t/(2q), yielding a clean symmetric t²/(4m) deficit, round 1).
ALWAYS: Replace "take n → ∞" in squeeze arguments with the Archimedean form (|D| ≤ C/n for all n ⇒ D = 0) — it removes any appeal to limits/continuity the rigor rules could question (round 1).
ALWAYS: Name the squaring step once as a principle ("for A,B ≥ 0, A ≥ B ⟺ A² ≥ B²") and invoke it by name at each use — satisfies the reviewer's positivity-at-every-squaring demand without repetitive boilerplate (round 1).
ALWAYS: Check `results/<id>/lemmas/` is actually nonempty before "importing" a certified lemma — dispatch may say "import once certified" while the dir is still empty; prove shared steps in full in your own file instead (imo-2026-05 round 1: lemmas/ empty at build time).
ALWAYS: When sibling builders prove identical shared steps in parallel, list them under `## Promotable lemmas` in your approach file rather than writing `lemmas/<name>.md` yourself — avoids two builders writing the same lemma file (round 1).
NEVER: Use a coarse bound the outline explicitly flags as lossy — in imo-2026-05 the crude bound (x+y+a) ≤ 2y+2a only killed b > 2a while the exact expansion killed all b > a; sympy-check the exact expansion, then derive it inline in the prose (round 1).
ALWAYS: Replace "let ε → 0" squeezes with one explicit ε value when the contradiction allows (imo-2026-05 orbit-forbidden-zone: ε = a/4 turned a limit argument into the one-liner a/4 > 3a/4 — no limiting appeal for the reviewer to question, round 1).
ALWAYS: In minimal-index/AP-chase arguments, treat the boundary index (minimal n = 0, or forced m ≥ 1) as its own sub-case — it often degenerates to exact equality that the generic strict inequality misses (imo-2026-05 Step 2.5: n = 0 forces f(y₀) = x exactly, round 1).
ALWAYS: If dispatch explicitly assigns you to write `lemmas/<name>.md` proposals, do so but mark them "proposed — pending proof-reviewer certification" and self-contained (state hypotheses fully); dispatch instructions override the general avoid-collision rule above, and the reviewer reconciles duplicates (round 1).
