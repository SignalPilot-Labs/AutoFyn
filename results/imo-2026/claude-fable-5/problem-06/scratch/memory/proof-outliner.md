# proof-outliner per-role rules

ALWAYS: for greedy "smallest next element with property P vs all previous" sequences, first test whether {terms} = {all m ≥ a_1 with P vs ALL terms} — the two-line minimality argument can turn "for all n" periodicity into set-periodicity and dissolve the transient/pull-back issue entirely (worked for imo-2026-06, round 1).
NEVER: define the essential prime set as "primes dividing infinitely many terms" — for a sequence containing all even numbers, EVERY odd prime divides infinitely many terms; use minimal hitting-set membership instead (two explorer reports stumbled on this, round 1).
ALWAYS: when the core object is a maximal intersecting family / self-blocking clutter, record the Δ_n guardrail (member sizes unbounded across instances) before proposing any size-bound lemma (round 1).
