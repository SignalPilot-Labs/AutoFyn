# outline-reviewer per-role rules

ALWAYS: before trusting an upper-bound *restricted strategy*, run a falsification sweep (random Liu configs, compute ratio = worst Liu odd-sum / target) — a restricted strategy that scores ratio > 1.05 for n>=2 is dead, do not register it as viable (because round 1: surrogate-adversary's R_n scored 1.05-1.37 and R_n' scored 1.37-1.46, both falsified; the approach had anticipated this in its "what would kill" section but the skeleton still shipped the dead engine).

ALWAYS: when an approach claims an upper-bound mechanism, brute-force the TRUE optimal Xiang response on a few hard configs and inspect the final piece structure — the mechanism named in the skeleton must match what the game's actual minimizer does (because round 1: the optimal Xiang creates near-equal PAIRS, confirming pairing-charging and refuting equal-split-largest).

NEVER: branch a COPY of a falsified mechanism into a threshold variant — run the falsification sweep on the variant first; if it also scores ratio > 1, reject the copy (because round 1: R_n' threshold-gated twin scored 1.37+, worse than the parent, a wasted twin).

NEVER: accept a dyadic-telescope upper bound on D = S_odd - S_even without checking the target ratio — naive telescope gives D <= 1/2^n but the target is 1/D_n ~ 1/2^{n+1}, a factor-of-2 gap (because round 1: alternating-potential's stated gap is a real wall, not an under-specification).

NEVER: accept a "convex + local-min ⟹ global-min on the <= n-cuts achievable set" argument without checking the feasible set IS convex — the <= n-cuts refinement set is NOT convex (multiset-average of two refinements need not be a refinement of the dyadic config; the cut-count cardinality constraint is non-convex); over the larger all-refinements convex set the min is 0 (split everything into equal pairs), so the cut-count is load-bearing. The convexity-of-order-statistics argument must restrict to a single convex face (one-cut-per-piece) + separate cross-face/boundary checks, or lead with a non-convex engine (parity-integral add/subtract). (because round 2: dyadic-induction's Route A claimed the achievable polytope is convex; I constructed a counterexample and the cut-count constraint is the load-bearing non-convex part.)

ALWAYS: when verifying the peeling lemma (D_final = D_rest when a split creates an equal pair), keep the ORIGINAL p_j in the final multiset — Xiang splits p_1, not p_j, so the original p_j STAYS and the new fragment p_j is ADDED (two copies of p_j total). Removing the original p_j gives a spurious discrepancy. (because round 2: my first verification pass had this book-keeping bug; after fixing, error = 0 on 20k configs.)

NEVER: accept an amortized-potential Φ = D − α·M (M a linear function of split-progress) as a genuinely-different upper-bound route — at peeling splits D_final = D_rest (D-neutral, no charge), and at non-peeling splits the non-increase ΔD <= α·ΔM is the same dyadic-decrement schedule that hits the factor-of-2 wall. A linear-in-split-progress potential collapses into the dead direct-D-cap. A viable potential must be non-linear in split-progress or defined on the parity profile j(t), not on D directly. (because round 2: alternating-potential's pivot crux step 3 is a "candidate M = Σ(splits)·2^{-k}", a weighted split count — structurally the same wall.)

ALWAYS: before approving a "worst Liu = dyadic" collapse approach via a flattening/Robin-Hood monotonicity lemma, numerically test the monotonicity using the EXACT min_Xiang D formula (for n=2: min(p_3, |2p_1−1|, p_1−p_2, p_2−p_3)) — Robin-Hood flattening (mass from largest to smallest) INCREASES min_Xiang D when p_3 is the binding constraint (because min_Xiang D = min(p_3, …) and p_3 grows under flattening), so the lemma is violated ~50% of the time. The conclusion (worst Liu = dyadic) may be true but the flattening-monotonicity proof route is dead. (because round 4: collapse-theorem's load-bearing flattening lemma was numerically FALSE for n=2, RETHINK'd.)

ALWAYS: when a surplus-chain / split-to-match chain claims "D = r_{n−1}" (lone surplus), check whether p_{n+1} (the smallest piece) is left unpaired — the chain p_1→p_2+r_1→…→p_n+r_{n−1} uses n−1 marks and pairs p_2,…,p_n but leaves p_{n+1} in the rest, so D = |r_{n−1} − p_{n+1}|, NOT r_{n−1}. The full n-mark chain (pairing p_{n+1} too) requires each intermediate r_k ≥ p_{k+1} (fails for flat configs where p_1 < p_2+p_3). (because round 4: pairing-charging + minimax-strategy-family both shipped the broken chain claim for n≥3; 18050/30000 n=3 configs give D ≠ r_2.)

NEVER: accept a "peeling-pair bound" that pairs fragments greedily (largest with second-largest) and invokes the peeling lemma to "cancel each near-equal pair" — the peeling lemma (lemmas/peeling.md) requires EXACTLY equal pairs (p_j, p_j) for parity-neutrality; "near-equal" pairs do NOT cancel (two equal pieces at adjacent ranks cancel, but greedy pairing of arbitrary fragments does not produce equal pairs). The numeric bound may still be TRUE (e.g. G1-iii-a D≥1, verified), but the peeling-lemma mechanism is the wrong proof; require a correct argument (parity-integral / dominant-M / direct overlap bound) instead. (because round 5: dyadic-induction's G1-iii-a "peeling-pair" mechanism misused the peeling lemma; CHANGES REQUESTED.)

NEVER: accept a "peeling recursion D = Σε_i + D_final" that iterates the D = M − D_R identity (Lemma 4-style, M the top-level dominant) on the REST R = floor ∪ F' — the identity D = ε_1 + D_alt(R'') holds for ONE peel (because M is the top-level dominant, so D = M − D_R = M − (M−ε_1 − D_alt(R'')) = ε_1 + D_alt(R'')), but the SECOND peel would need M to be the dominant of R'', and M is GONE from R'' (it was the top-level piece, not in the rest). The recursion does NOT telescope. For the n=4 tight config F'={7.5,4.5,2,1,0.5,0.5} (M=8, floor={4,2,1}): Σε + D_alt(floor) = 32+3 = 35, but actual D = 1. Verify by direct D_alt computation that any claimed "Σε_i + D_final" identity holds BEFORE accepting it. (because round 6: dyadic-induction's G1-iii-a peeling recursion was the THIRD failed mechanism — wrong by 35×; the bound D≥1 is true but needs a different proof.)

ALWAYS: verify a "this sub-case is EASIER / has GROWING slack" claim by an EXACT search for the TIGHT config, not just a coarse grid — coarse grids (step 1/2, r≤4) miss tight configs. For G1-iii-a, the explorer's coarse sweep reported "n=4 min D≈1.24, n=5≈3.08, n=6≈4.22 (growing slack, iii-a easier)"; an exact integer search found min D = 1 at n=4 (F'={7.5,4.5,2,1,0.5,0.5}) AND n=5 (F'={15.5,7.5,4,2,1,0.5,0.5,0.5,0.5}) — iii-a is TIGHT (D=1) for all n≥4, NOT "easier with growing slack." The "easier" premise was numerically false and would have misdirected the builder. (because round 6: dyadic-induction's iii-a prioritization rationale was based on a numerically false claim.)

ALWAYS: when an approach invokes "max of PWL at a vertex" (Bauer / Piecewise-concavity smoothing), check the direction of the extremum — the MAX of a CONVEX PWL function is at a polytope vertex (Bauer max principle), but the MAX of a CONCAVE PWL function (min of linear) can be in the INTERIOR. The GENERAL correct statement: the max of ANY PWL function on a polytope is at a vertex of the cell complex (intersection of arrangement hyperplanes, including induced breakpoints from the recursive min structure), NOT necessarily a vertex of the polytope itself. The cell-complex vertex count (C(H, dim) for H arrangement hyperplanes) can be much larger than the polytope vertex count; require the builder to bound it or fall back to a sub-case table. (because round 6: pairing-charging's n=4 vertex enumeration correctly invokes the general PWL result, but the vertex count includes induced peel-menu breakpoints, not just the ~70 polytope-boundary vertices — the anti-stuck fallback covers the explosion risk.)
