# proof-reviewer — per-role rules

ALWAYS: re-derive the load-bearing lemma's algebra with python3 (sympy/Fraction) before certifying — a plausible-but-wrong lemma is worse than an admitted gap (round 1: caught the ΔA sign-convention subtlety and confirmed the formula only after fixing the test's tail-sign convention).

ALWAYS: when a lemma is "proved" in one approach but the SAME lemma appears in a sibling, check BOTH proofs independently — they can differ in rigor (round 1: Lemma G was rigorous in `pairing-partner` but the upper-bound half was flawed in `induct-one-mark`; certified only the rigorous version and flagged the overclaim).

ALWAYS: hunt for the "exactly the top k pieces are gone" / per-piece-bound fallacy in any greedy-game proof — the per-piece claim is typically false under deviation even when the total bound holds (round 1: counterexample pieces 5,4,3,2,1, Liu deviates to p_3, 2nd piece = p_2 > p_3).

ALWAYS: check edge cases at boundary parameters (a=1/2, a=1/3, ε→0, the threshold itself) — the sliver/bisect mode split in U(1) had a one-point hole at a=1/2 because the sliver required ε < 1−2a = 0 (round 1).

NEVER: trust a "symmetrically" / "by the same invariant logic" upper-bound argument without re-deriving it — the symmetry often breaks in one direction (round 1: induct-one-mark's Xiang-upper-bounds-S_odd argument was the broken half).

ALWAYS: when a builder proposes a lemma but leaves the file unwritten ("to be written if the reviewer approves"), write the file yourself if the lemma passes the bar — the shared cache is the deliverable, and an unwritten certified lemma is invisible to the next round's builders. (round 2, imo-2026-03, U(2) four-strategy lemma.)

ALWAYS: verify the DIRECTION from which a sliver strategy's value approaches its infimum. "Inf ≤ target" is necessary but not sufficient for the upper bound — the actual value must approach the infimum FROM ABOVE (so small sliver gives strict < target for non-extremal configs). Check `Liu(s) ≥ inf` for small s>0. (round 2, imo-2026-03, U(2) sliver strategies.)

NEVER: accept "exact" for a strategy that degenerates at a config boundary (e.g. Strategy A "match 2nd-largest in largest" at c=b gives zero sub-pieces / coincident marks). At the boundary it is an infimum; the bound may still hold via other strategies, but the "exact" label is an overclaim. (round 2, imo-2026-03, U(2) Strategy A.)

ALWAYS: when a builder concedes their own central strategy is a "rephrasing not a bypass" of the two main gaps (L+U), record the outcome as `partial` (not `advanced`) and flag the approach for retirement or re-conception — a conceded-dead route is not real progress even if its sub-results are correct. (round 2, imo-2026-03, induct-one-mark.)

ALWAYS: when spot-checking a picking-game lower bound with random Xiang marks, include LIU's marks in the piece-construction (combine both players' marks before sorting) — a test that omits Liu's marks produces bogus "violations" from configs that aren't actually game positions (round 3, imo-2026-03: my first pass flagged false violations of L(3) purely because `pieces_from_marks` only took Xiang's marks; the bound holds 0/300k once Liu's marks are included).

ALWAYS: when certifying a "cancels iff X" greedy/multiplicity lemma, test the EVEN-multiplicity-pre-step case (m even) — the parity conclusion often flips (round 3, imo-2026-03: the dyadic-ratio overshoot corollary "cancels iff a_1 > 2 a_2" is FALSE for m even; counterexample (6,3,3) dyadic-ratio but m=2→4 even, cancels; the "iff" is valid only for m odd/generic m=1).

NEVER: accept a reduction lemma's headline "0 violations on N random reals" without re-running the spot-check yourself with the correct mark budget and Liu's marks included — builders' 500k-sample claims have been reliable so far, but the verification is cheap and catches both builder bugs and reviewer-own test bugs (round 3, imo-2026-03).

ALWAYS: when reviewing a piecewise-linear / vertex-enumeration lower bound, do NOT reject it on the "minimizer is a flat facet, not a unique vertex" worry — for an affine function on a compact polytope, the minimum is ALWAYS attained at a vertex; a flat facet where the function equals its min has all its vertices at the same min value (affine functions have no strict interior minima). The vertex check validly covers flat minimizers. The flat-facet analysis is needed only for EQUALITY CHARACTERIZATION, not for the BOUND. (round 4, imo-2026-03: cell-complex-l3's L(3) vertex enumeration is valid despite the flat minimizer — verified by perturbing the mirror config: shifting all marks preserves A=1/15 (flat direction), single-mark perturbations increase A or stay flat; the 5 boundary-vertex multisets all attain A=1/15.)

ALWAYS: when verifying a piecewise-linear enumeration, separately confirm (a) the arrangement is COMPLETE (every cell boundary is captured — piece-equality for sort changes, piece-zero for distribution changes / coincidences / endpoints), (b) the parametrization is valid (sub-piece lengths as a multiset are equivalent to mark positions for the alt-sum, since the alt-sum depends only on sorted-desc), (c) degenerate vertices (≥4 active hyperplanes) are captured by a rank-3 triple subset. Re-run the enumeration script AND an independent direct-from-marks sanity check (grid + random) — both must give 0 violations (round 4, imo-2026-03: cell_vertex_exhaustive.py + sanity_check.py cross-confirmed).

ALWAYS: when verifying an "upper bound contradiction" proof (a family of cap strategies + a min≤α contradiction), re-derive the CONTRADICTION algebra independently (assume all caps > α, chain the inequalities, check both sign-split cases close) AND spot-check computationally — the contradiction logic is the load-bearing step and a missing case (e.g. an unhandled sign of an absolute-value cap) sinks it. (round 5, imo-2026-03: verified the 5-cap U(3) contradiction `min(a, b−a, c−b, 2d−1, |a+b−c|) ≤ 1/15` by re-deriving both Case i and Case ii and confirming 0 violations on grids + 50k reals.)

NEVER: accept "computationally verified 0 violations" as a substitute for a proof when the builder themselves flag a region as an open GAP — a material GAP is material even if the numeric check is clean; record Status partial and route to CHANGES REQUESTED. (round 5, imo-2026-03: two-regime-disjunctive's `d < 1/2` extreme sub-cases `w < −2α` or `z < −2α` are 0-violation computationally but the analytic 17-family case-by-case is NOT written — this is a MATERIAL GAP that prevents `c(3) = 8/15` end-to-end.)

ALWAYS: when a builder FALSIFIES their own central conjecture (e.g. strict-decrease `Φ > 0 ⟹ cap < α` killed by a ridge config), verify the falsification is genuine (re-derive the pair-pile cap on the counterexample AND the Φ value), certify the harvestable partial lemmas to the cache, and route the approach to RETHINK (re-conceive or retire) — a dead central route is not a live approach even if its sub-lemmas are rigorous. (round 5, imo-2026-03: dyadic-halving-induction's ridge `R_e = (8,4,2+e,1−e)/15` has `Φ = 5e > 0` yet `cap = α(3)`; two lemmas harvested, approach RETHINK.)

ALWAYS: when a builder corrects a previously-certified lemma in place (removing a false corollary / re-scoping a proof), UPDATE the lemma file yourself and mark the correction prominently — a stale false corollary in the shared cache poisons every approach that imports it. (round 5, imo-2026-03: pairing-partner's round-4 `σ ≤ M/2 = a_1` corollary was FALSE for `k ≥ 2` (counterexample `m=(3,3,1,1)/15`); removed from `lemma-superincreasing-R.md`; L3-unrefined-R re-worked via the m_1-split into Branch 1 (m_1 ≥ a_1) + Branch 2 (m_1 < a_1).)

ALWAYS: when a builder claims an equivalence `L ⟺ Hall-matching-existence` via a SUM inequality (Match) Σ m ≤ Σ r, reject it — the total sum is only a NECESSARY condition for Hall (per-subset |N(S)|≥|S|), NOT sufficient. Counterexample L={3,3}, R={5,1}: sum holds, no matching. The correct one-directional statement is φ-existence ⟹ L (sufficient, not equivalent). (pairing-partner Reduction D overclaim, round 6)

ALWAYS: for "cap = |linear combination|" strategies computed via the equal-pair cancellation lemma, verify the lemma's even-case claim (the two odd-multiplicity blocks contribute +larger, −smaller = |difference|, because the earlier block starts at an odd rank). Proof: after removing the 2 singleton positions, each maximal run of remaining positions has even length (tileable by length-2 equal-pairs); this forces i odd, j even for the singleton positions i<j. Robust to coincidences by continuity of the alternating sum across sort boundaries. (two-regime-disjunctive §5e.1 C6/C7 realizability, round 6)

NEVER: trust a "computationally 0 violations" result OR an LP max-t<0 as the proof — they are corroboration. For the 7-cap U(3) closure, the load-bearing step is the hand-derivation of all 8 sign-triple sub-case contradictions in chain-excess coordinates; re-derive each independently (the algebra is ≤4 lines per sub-case and checkable). (two-regime-disjunctive §5e.3, round 6 — APPROVED because the hand-derivation is sound, not because of the script)

NEVER: certify a builder's PROPOSED lemma that is honestly labeled "conjecture / verified n=k but no general-n proof" (e.g. lemma-d3-fractional-vertices) — it is a tracked OPEN problem, not a proved lemma. Reject certification but leave the file as a record. (cell-complex-l3, round 6)

ALWAYS: when a builder overturns a prior round's "no small subfamily suffices" ruling, verify the overturn is on the RIGHT axis. The round-5 ruling counted un-realizable cap VALUES (d−b−c needing d≥b+c); the round-6 7-cap family enforces REALIZABILITY (strategies, not values) and excludes the un-realizable caps. The correction is sound only because all 7 caps are always-realizable (none needs d≥b+c or d≥1/2). (two-regime-disjunctive §5e.1, round 6)
