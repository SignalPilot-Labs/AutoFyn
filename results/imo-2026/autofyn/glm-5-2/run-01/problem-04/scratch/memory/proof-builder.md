# proof-builder per-role rules

ALWAYS: record a failed engine as an explicit dead-end under ## Approaches tried with the concrete counterexample (e.g. the (3,2,3) fixed point for the greedy t=1 transfer), because the reviewer and next-round outliner grep for dead-ends to avoid re-dispatching the same route (round 1, imo-2026-04 chip-transfer).
ALWAYS: verify load-bearing algebra with a quick python3/sympy computation before writing the proof, and paste the one-line identities into the proof text — the reviewer flags "asserted without derivation" as CHANGES REQUESTED (round 1, imo-2026-04 four-case closure telescoping).
NEVER: claim a "distinct" necessity engine when the geometry forces a single closure; the outline-reviewer refuses near-duplicates (modular-residue-orbit was refused round 1 for restating the four-case algebra). Honestly label shared engines and the approach still earns partial credit (round 1, imo-2026-04).
