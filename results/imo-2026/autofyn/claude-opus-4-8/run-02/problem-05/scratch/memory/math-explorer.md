ALWAYS: for functional-inequality problems with two chained inequalities (e.g. QM-AM >= mid >= AM-GM shape), try substituting one variable to equal f(other var) — this often collapses one side of each inequality to a trivial degenerate equality (QM-AM/AM-GM with equal arguments), forcing the OTHER comparison into an exact equality/FE for free (round 1, imo-2026-05).
ALWAYS: numerically test the diagonal x=y (or other symmetric) substitution FIRST to check it isn't vacuous before spending report space on it (round 1, imo-2026-05: x=y was vacuous, both sides reduce to trivial QM-AM/AM-GM on (x,f(x))).
NEVER: assume "determine all functions" IMO problems necessarily have a single answer like f=id — check numerically whether a whole parametrized family (e.g. f(x)=x+c) satisfies the inequalities before committing the report to a single-function conjecture (round 1, imo-2026-05: f(x)=x+c, c>=0 all work).
ALWAYS: for two-sided chained inequalities (sqrt(...) >= mid >= sqrt(...)), try plugging one variable as f(other) into the WHOLE chain at once — both inequalities from the same substitution often force an exact equality/FE (worked for imo-2026-05: x=f(y) gave f(f(y))=2f(y)-y). (round 1)
NEVER: trust that solving a derived functional equation alone characterizes all solutions to the original inequality — always numerically stress-test a candidate that satisfies only the derived FE (e.g. piecewise jump functions) against the FULL original inequality before claiming it's ruled out or ruled in (round 1, imo-2026-05: FE alone admitted a piecewise f that badly violated the original chain).
