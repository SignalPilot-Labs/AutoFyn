ALWAYS: simulate/execute multi-step forcing algorithms (game strategies, iterated reductions) with exact arithmetic (Python `fractions.Fraction`) on random inputs BEFORE writing the final proof — a naive/greedy re-implementation of a forcing algorithm can silently cycle or stall even when every individual lemma is algebraically correct, because the *dispatch logic between phases* (which lemma fires next, on which coordinate) is a separate thing from the lemma statements and is easy to get subtly wrong (round 3, imo-2026-04: a "generic room-condition dispatch" re-applied naively after a reduction step caused an infinite null-move cycle; the fix was to make the algorithm target the *known* constant produced by the prior step directly, not re-run generic case analysis on it).
ALWAYS: when a proof produces a "universal constant" coordinate via an identity (e.g. `180−θ` appearing regardless of the starting triangle), have the finishing phase of the algorithm operate on that literal known value, not re-derive/re-classify it via the general case split — state this explicitly as a distinct proof step, since reviewers will flag it as an unjustified hand-off otherwise (this was exactly the outline-reviewer's Gap 1 in imo-2026-04).
ALWAYS: for "Shan-Yu/adversary survives forever" (invariant-preservation) directions, prefer a single closed-form initial construction in terms of the free parameter (e.g. `(θ/2, θ/2, 180−θ)` for all θ) over "generic/measure-zero" language — it is usually easy to find and makes the proof airtight instead of hand-wavy, and reviewers explicitly reject "generic" as insufficient per CLAUDE.md rigor rules.
ALWAYS: strip stray LaTeX commands (`\iff`, `\notin`, `\text{...}`, `\{...\}`, `$...$`) from the final Markdown proof file — this repo's proofs are prose Markdown, not rendered LaTeX, and leftover TeX commands (easy to introduce when drafting quickly) read as sloppy/unrendered noise to a reviewer. Grep for `\\` before finalizing.
NEVER: trust a "worked example" trace by hand alone for a multi-step forcing algorithm without also running an independent computational check (sympy for algebraic identities, exact-fraction simulation for the full algorithm) — hand tracing is error-prone exactly at the phase-transition points where bugs hide.
