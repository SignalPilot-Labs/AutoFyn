ALWAYS: for geometry problems, check crux_moves_documentation.md before querying the corpus — geometry currently has ZERO extracted cruxes (only number_theory/combinatorics/algebra), so don't waste time querying it for geometry problems (round 1).
ALWAYS: when a geometry problem's constraints under-determine the configuration (e.g. 3 equations for 4 unknowns), numerically solve for a whole 1-parameter family (not just one instance) via fsolve/scipy and check whether the target quantity (e.g. OM=ON) holds identically along the family — this often reveals a stronger fixed-line/fixed-point fact (e.g. O sweeps a fixed perpendicular bisector) that is the real theorem to prove, round 1, imo-2026-02.
ALWAYS: when a problem's hypotheses have visible relabeling symmetry (e.g. swap B<->C, K<->L, M<->N), explicitly write out how each condition transforms under the swap — it may be a symmetry of the equations without being a rigid symmetry of the figure (spiral similarity/congruence); verify numerically before assuming congruent sub-triangles, round 1, imo-2026-02 (BMK vs CNL numerically NOT congruent despite the swap symmetry existing).
ALWAYS: when a constraint system underdetermines the configuration (fewer equations than unknowns), sweep the free parameter with least_squares/fsolve continuation (warm-start from previous solution) and check if the target quantity is invariant along the WHOLE family, not just at one solved instance — for imo-2026-02 this showed OM=ON holds identically across the full 1-parameter family of (K,L), meaning the "interior/angle-containment" hypotheses likely only fix a branch, not add real constraining power; this is a strong structural clue worth reporting explicitly (round 1, imo-2026-02).
NEVER: assume O (or any constructed point) is a fixed named triangle center just because it satisfies the target property at one solved instance — check across the swept family first; for imo-2026-02, O is NOT the circumcenter/orthocenter/a fixed point at all, it moves along the perpendicular bisector of MN as the free parameter varies (round 1, imo-2026-02).
ALWAYS: when placing B,C symmetric about the origin (B=(-1,0),C=(1,0)) with A=(p,q) free, M=(A+B)/2 and N=(A+C)/2 automatically share the same y-coordinate (q/2) — so OM=ON collapses to the 1-dimensional scalar condition O_x = p/2, not a full 2D distance identity. Big simplification for coordinate-bash routes, round 1, imo-2026-02.
ALWAYS: when numerically solving angle-equality systems (arccos-based, unsigned) via fsolve, cross-check the found root against ALL the problem's stated containment/orientation hypotheses (inside triangle, inside angle X) before trusting the result — fsolve happily returns "other branch" roots satisfying the unsigned angle equation but violating orientation, and these give a visibly different (false) answer for the target quantity. A clean break in the target's truth exactly where an orientation condition flips is strong evidence the true proof must use that orientation hypothesis, not just the equality of angles, round 1, imo-2026-02.
ALWAYS: when hunting for a single-circle/single-spiral-similarity synthetic mechanism for an angle-equality hypothesis "∠XVY = ∠X'V'Y'" (vertex V vs V'), only ONE of the two AA conditions for a spiral similarity is given by the hypothesis (angle-at-image-vertex); numerically check the COMPANION angle (angle at the pivot) and the length ratio before assuming the spiral similarity holds — for imo-2026-02, two natural spiral-similarity/concyclicity guesses built from conditions ∠LBK=∠LNC and ∠LCK=∠BMK both failed this check by ~100+ degrees, ruling them out cleanly and cheaply (round 2, imo-2026-02).
NEVER: assume a nicely-named auxiliary point (e.g. midpoint M or N of a side) lies on a constructed circle (e.g. circumcircle of AKL) just because it seems structurally natural — check |O-point|-R numerically first; for imo-2026-02, M and N do NOT lie on the circumcircle of AKL despite M,N being central to the problem (round 2, imo-2026-02).
ALWAYS: for a ray-parametrized configuration K=V1+r1*u1(theta), L=V2+r2*u2(theta) with u1,u2 fixed directions independent of r1,r2, check numerically whether each angle-equality hypothesis "at a vertex" actually depends on only ONE of r1,r2 (angles at a vertex V involving a ray whose direction is fixed regardless of one parameter are independent of that parameter) — this can fully DECOUPLE a coupled 2-var branch/Groebner problem into two independent 1-var monotone equations, sidestepping spurious algebraic branches entirely without Positivstellensatz machinery (round 2, imo-2026-02: F1=angleLBK-angleLNC depends only on r2, F2=angleLCK-angleBMK only on r1).
ALWAYS: when a target reduces to "constructed point P satisfies PB=PC" (isosceles/perp-bisector target), numerically sweep the free parameter of the hypothesis-satisfying family and check whether the ANGLE that ray BP makes with a fixed reference ray (e.g. BA) is a simple additive function of the free parameter plus a base-triangle angle (e.g. angle(BA,BP) = theta + 90 - angle_C) — this kind of exact linear-in-theta angle formula, if found, converts the whole PB=PC target into an elementary angle-chase (P B C isosceles via base angles) that needs NO further reference to the original construction points, a much smaller target than the raw equality (round 3, imo-2026-02: found angle(ABA*)=theta+90-gammaand angle(ACA*)=theta+90-beta hold exactly across 3 triangle shapes, reducing A*B=A*C to two scalar angle lemmas).
NEVER: assume an exact-looking numeric angle identity found at hypothesis-satisfying (r1,r2) also holds at ARBITRARY (r1,r2) for the same theta before checking — it usually does NOT (the identity is a genuine consequence of the full hypothesis system, not of the ray-direction/theta alone), so don't claim it "decouples away" r1,r2 without testing mismatched r1,r2 explicitly (round 3, imo-2026-02).
ALWAYS: when asked to find a "genuinely different framing" (not a variant of the shared-gap wall), first test whether the natural "symmetry/rigid-map" idea actually holds as a FIXED structural fact BEFORE proposing it — e.g. for a target OM=ON with M,N fixed midpoints, the perpendicular bisector of MN is a FIXED line (t-independent) once M,N are fixed, so you can cheaply test "does reflecting across it swap B<->C / K<->L" with one fsolve call at any single t; for imo-2026-02 this reflection does NOT swap B,C (fixed nonzero residual ~0.3, same across t, confirming it's a real structural fact not noise) — a fast, cheap way to kill or confirm a whole symmetry-based framing before recommending it (round 3, imo-2026-02).
NEVER: report "no obvious named point" findings without also checking a handful of concrete ratio/incidence candidates (AK/AM, AK/AC, AL/AB, AK*AC, orthocenter/midpoint-of-BC on the constructed circle) across at least 2 non-isosceles triangles — cheap fsolve+ratio checks (a few lines of code) can rule out a whole class of "K or L is a named center" guesses in minutes, saving the outliner from proposing a lookup-based approach that a 5-minute numeric check would have killed (round 3, imo-2026-02).
ALWAYS: when a reviewer finds a counterexample to "F monotonic on domain (0, Xmax)" where Xmax comes from ONE containment hypothesis (e.g. "L inside triangle BNC"), check whether a DIFFERENT containment hypothesis used only informally as a "sign convention" (e.g. "K inside angle LBA") defines its OWN, possibly smaller, boundary on the same parameter — the counterexample may live entirely outside that second true boundary, meaning the fix is "shrink the domain to the true intersection of ALL hypotheses" not "abandon monotonicity/IVT." For imo-2026-02, restricting r2 to (0, min(r2max, r2_signflip)) instead of (0, r2max) made both the false monotonicity claim AND the false global inequality (star) become non-issues simultaneously (2300+ numerical trials, zero counterexamples) — always test this domain-correction hypothesis with numerics before recommending abandoning an IVT/monotonicity route (round 3, imo-2026-02).
ALWAYS: when a prior round produces a degree-<=2 "angle-matching on a ray" polynomial Q(r) (mod-pi equality, ambiguous branch) as a substitute for a transcendental angle equation, and a separate scalar target (e.g. circumcenter coordinate = fixed value) is still open, test computationally whether the target is an UNCONDITIONAL polynomial consequence of Q=0 alone (via sympy multivariate polynomial division AND an independent Groebner-basis reduction of the cleared-denominator target against the ideal (Q2,Q1) as a cross-check) before assuming the earlier "raw angle-equality polynomials don't force the target" Groebner finding still applies; a rescaled ray variable (R=r*|side length| instead of r) can make ideal membership succeed even when a previous round's Groebner attempt on the raw arccos-based system failed, and if the remainder is 0 for BOTH roots of Q, the "branch selection" caveat blocking the lemma's promotion becomes IRRELEVANT to the final target -- always numerically instantiate ALL root-combinations to confirm this before reporting it (round 4, imo-2026-02: Q2(R1)=0 AND Q1(R2)=0 implies O_x=p/2 unconditionally, verified both symbolically and at all 4 numeric root-combinations).
NEVER: trust a "linear-in-theta angle formula" (e.g. angle(ABA*)=theta+90-gamma) as unsigned-valid across the whole triangle-shape domain without testing an OBTUSE case for the "other" angle (gamma here) — for imo-2026-02 the formula flips to |theta+90-gamma| once gamma>90+theta (confirmed via fsolve on (p,q)=(1.5,0.8), gamma=122°), with the underlying geometric configuration (which point sits angularly between which) flipping exactly at that sign boundary; always sweep at least one deliberately skewed/obtuse (p,q) before declaring a formula "exact, no absolute value needed" (round 4, imo-2026-02).
ALWAYS: when hunting for a synthetic shortcut linking a constructed point (e.g. antipode A*) to two other points via two intermediate points (K,L), brute-force test ALL 4-point-subset concyclicities among the named points (a ~70-combo loop with a determinant-based concyclic_measure function, a few seconds) before proposing a specific cyclic-quadrilateral guess — this cheaply rules out a whole class of "the hypothesis angle equalities directly encode quadrilateral BKLN cyclic" guesses in one script run (round 4, imo-2026-02: none of C(8,4)=70 subsets of {A,B,C,M,N,K,L,A*} were concyclic beyond the two already-known trivial circles).
ALWAYS: when scouting a "genuinely new framing" involving a composite map (e.g. inversion-plus-reflection swapping two vertices), verify each classical sub-fact (perpendicularity, distance formulas) with a controlled, minimal, single-purpose numerical test using RANDOM points that need NOT satisfy the problem's hypotheses (general theorems are hypothesis-free, avoiding conflation of "false fact" with "solver found wrong branch") — a sloppy inline test wrongly suggested "parallel" instead of "perpendicular" for an inversion-image-line direction fact; redoing it as an isolated, careful test gave the correct answer (perpendicular, to 1e-16), matching classical inversive theory. Suspect your own quick script before doubting standard theory (round 4, imo-2026-02).
NEVER: use a bare fsolve on only the angle-equality equations (dropping containment/orientation hypotheses) to numerically test a NEW candidate identity for the actual problem configuration — it reliably lands on a geometrically invalid branch (OM != ON at the "solution"), which looks like a refutation but is really just solver branch selection; a known trap since round 1, easy to re-trip when building a quick probe script for a fresh framing (round 4, imo-2026-02).
