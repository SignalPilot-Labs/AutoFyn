## imo-2026-06 (computational/concrete-S exploration)

### CRITICAL REFRAMING (read this first)
Per `/tmp/memory/math-explorer.md` rule #8 (apparently written by a parallel
explorer this same round) and independently consistent with my own data
below: **the "central gap" as stated in `current.md` — "prove
S := {p : p | a_n for infinitely many n} is finite" — is targeting a FALSE
statement, not just a hard one.** Reasoning: if `a_{n+T}=a_n+L` holds
eventually (the very thing to be proved), then for ANY prime `p` (dividing
`L` or not), consider the residues `a_{r+kT} mod p` for fixed `r`: they
increase by `L mod p` each step in `k`. If `p ∤ L`, this residue cycles
through *all* residues mod p periodically, hitting 0 once every `p` steps —
so `p` divides infinitely many terms with density `1/(Tp)`. If `p | L`, the
residue is constant in `k`, so `p` divides infinitely many terms iff it
divides one term in the period, which happens for at least one prime per
residue class by the certified "every term meets a recurring prime" lemma.
Either way, **essentially every prime that ever divides any term also
divides infinitely many terms** — so `S` (literally as defined) is in fact
infinite (or at least does not need to be finite) for essentially any
eventually-periodic sequence. This matches my own numeric observation below
(e.g. `a_1=385`'s "primes in last 500 terms" list contains dozens of large,
one-off-looking primes in the thousands — these are not noise, they are
exactly the low-density recurring primes the argument above predicts).
**The correct finite target is not `S` but `L` (equivalently, the finite set
of primes dividing `L`)** — my data below is directly about `L` (and `T`)
and remains valid and useful; only the old "finiteness of S" framing should
be dropped. The outliner should retarget the central gap as: *identify/bound
the finite modulus `L` (or show SOME finite `L` works)*, not "show only
finitely many primes ever recur."

### Key findings

1. **S is emphatically not simply `rad(a_1)`.** Two independent phenomena,
   both confirmed by direct trace inspection (not just difference-period
   detection):
   - **Dropping**: a prime factor of `a_1` can vanish from `S` entirely. For
     `a_1 = 21 = 3·7`, traced by hand through 60 terms: from `a_2 = 24`
     onward *every single term is a multiple of 3*, and 7 never returns —
     because 3 is dense enough (gap ≤ 3) that the "always jump to the next
     multiple of 3" strategy is unbeatable once started, so the greedy
     literally never again needs 7. Same phenomenon for `a_1 = 33 = 3·11`,
     `63 = 3²·7`, `55 = 5·11` (drops 11, keeps only 5).
   - **Recruitment**: a prime *not dividing `a_1` at all* can enter `S`
     permanently. For `a_1 = 15 = 3·5`, traced by hand: `a_3 = 20 = 4·5`
     satisfies `gcd(20,15)=5` and `gcd(20,18)=2` — i.e. it clears the two
     "live" constraints using *two different* primes (5 and 2), and this
     split-coverage candidate is strictly smaller than the next pure
     multiple of 3 (21). Because it's smaller, the greedy rule takes it,
     permanently pulling 2 into the active set. This never happens for
     `a_1 = 21` because no analogous small split-coverage candidate beats
     the pure-multiples-of-3 strategy there (checked directly: 22, 23 have
     no common factor with 21 or with 24).

2. **Whether a prime is dropped or new primes are recruited depends on a
   delicate size-competition between "single dense prime" candidates and
   "split-coverage" (multi-prime, smaller) candidates** — not on any clean
   arithmetic function of `a_1` alone that I could find. Evidence against a
   clean closed form: `(3,5)` recruits 2 (15, 45) but `(3,7)`, `(3,11)` do
   not (21, 33, 63); `(5,7)`, `(5,13)` recruit but `(5,11)` does not (55 is
   the *only* pure-single-prime case among the two-large-prime pairs
   tested); `(7,11)`, `(7,13)`, `(11,13)` all recruit heavily (2, sometimes
   3). No simple rule (e.g. "recruit iff the two primes are twin/close")
   fits all these — the mechanism is a genuine covering-competition, not a
   formula.

3. **Transient length is highly variable and can be very long.** `a_1 = 385
   = 5·7·11` (three "large" primes, none equal to 2 or 3) does *not*
   stabilize within 40,000 terms / periods up to 2000 — the last diffs
   still show no repeating block, and terms in the low thousands still
   involve primes in the several-thousands range. This is a strong
   (numerical) sign that the true transient before `S` stabilizes can be
   arbitrarily long relative to `a_1`'s size, i.e. any proof of finiteness
   of `S` cannot rely on an explicit/small bound on the transient length as
   a function of `a_1` alone — reinforces the outline-reviewer's existing
   observation (from `jacobsthal-covering-bound.md`) that `T` (and now also
   the transient-to-stabilize length) is history-dependent, not a clean
   function of `a_1`.

### Verdict on the "explicit S(a_1)" route
**Not promising as a target for a proof.** The data show `S` is governed by
a genuine competitive-covering dynamic (dense single primes vs. smaller
split-coverage composites) with no evident closed form; attempting to
*characterize* S explicitly as a function of a_1 looks at least as hard as
proving abstract finiteness, and probably harder, since it would require
classifying exactly this size-competition for arbitrary a_1. The
`jacobsthal-covering-bound` approach's own "self-sufficiency" stopping
criterion (S_j is self-sufficient once its covering gap g(S_j) beats any
possible new-prime alternative) is the right *qualitative* reformulation —
it doesn't need a closed form for S, only a proof that some self-sufficient
state is reached in finitely many recruitment steps. That remains the real
target; my data doesn't close it but does confirm the criterion is the
right shape (every stabilized example I found, once in its periodic regime,
never introduces a genuinely new prime again — consistent with
self-sufficiency having been reached).

### Distinct openings for the outliner
- (a) Do **not** pursue a closed-form S(a_1) — confirmed dead end by
  the data above (dropping AND recruitment both occur, with no clean rule).
- (b) Reformulate the central gap using the concrete **self-sufficiency
  criterion**: define, for a finite prime set S_j, `g(S_j)` = the covering
  gap (finite for any finite nonempty S_j, trivially ≤ min(S_j)); argue that
  once the current active set is self-sufficient in this sense, no further
  recruitment is possible — this is the same content as before but gives a
  crisp, checkable per-step stopping condition to induct on, rather than an
  abstract counting bound (which is now confirmed insufficient, see
  round-1 dead ends below).
- (c) Consider instead directly bounding **how many times a strictly new
  prime can be "cheaper" than all currently-active-S alternatives** — since
  recruitment happens exactly when a split-coverage candidate (using a new
  prime for one historic constraint, active primes for the rest) beats the
  purely-S-covered candidate, and this requires the new prime to be
  small enough / the specific residue arithmetic to align — an approach
  bounding the multiplicity of such alignments (e.g., via a quantitative
  argument on how rarely a "cheap split" can occur before the growing S
  itself becomes dense enough to preempt it) might be more tractable than
  a naive global counting bound. This is essentially a refined version of
  the jacobsthal approach's phase induction, now with concrete numeric
  examples (15, 35, 65, 99 etc.) available as test cases for any candidate
  lemma.

  and requiring the greedy-minimality property essentially, not a soft
