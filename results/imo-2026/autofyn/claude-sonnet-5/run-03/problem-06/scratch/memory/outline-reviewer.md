ALWAYS: numerically simulate the greedy sequence (python3, gcd-based) for a few small a_1 values before judging outlines on "greedy-gcd sieve" problems (imo-2026-06 style) — it cheaply confirms/refutes concrete claims like "L = product of a_1's prime factors" or "T is a function of S/L alone" (round 1: found a_1=21,33 stabilize S to a proper subset of a_1's prime factors, and a_1=35 vs 105 share L=210 but have different T=34 vs 58, confirming the outline's own caveat).
NEVER: treat "all approaches converge on the same hard lemma" as an automatic same-framing collapse — check whether the mechanisms attacking that lemma are genuinely different (density threshold vs. quantitative counting vs. a-priori state space vs. phase induction); if so it reflects the problem's real bottleneck, not lack of diversity (round 1, imo-2026-06).
ALWAYS: when an approach's own outline text flags its own step as "circular unless argued more carefully" (a self-admitted gap), elevate that to an explicit CHANGES REQUESTED item telling the builder to resolve the circularity FIRST before investing in later, dependent lemmas — don't let a self-flagged circularity slide through as just another "open gap" bullet (round 1, imo-2026-06 growth-rate-contradiction).
ALWAYS: check file mtimes (`ls -la` / `date -r`) on results/<id>/approaches/*.md against the outliner's report mtime before trusting "the outliner writes there directly" — a report that reads as if it edited the approach files can in fact just be prose in the outliner's own chat/report file, never persisted to disk (round 2, imo-2026-06: outliner's report was 30min newer than every approach file and none contained any of the claimed revisions). If this happens, transcribe the outliner's plan into the actual approach files yourself before ranking/handing off a build set — otherwise builders silently rebuild on stale, possibly-refuted premises.
NEVER: wave through a "necessary condition" or "monovariant" lemma in an outline just because it sounds quantitative — test it with a 2-line counterexample first. Round 2 imo-2026-06's growth-rate-contradiction proposed "p_0 < g(Q) is necessary for a fresh prime p_0 to be recruited" (candidate m within window g(Q) of a_n, divisible by p_0, so p_0 ≤ m-a_n); this is false in general (choose a_n ≡ -1 mod p_0 for ANY p_0 — first multiple lands at distance 1). A plausible-sounding inequality about "the first multiple of p" can still be arbitrarily close by residue alignment; always check this class of claim against a small explicit example before approving.
NEVER: accept "since the state space is finite, by pigeonhole [specific starting state] recurs" as a valid step — pigeonhole on infinite-domain/finite-codomain only guarantees SOME value recurs infinitely often, not that a named specific value (e.g. σ(1), the initial state) is among the recurring ones; this is the standard eventually-periodic-orbit trap (a transient point need not lie on the eventual cycle). Caught in round 2, imo-2026-06 active-set-stabilization's proposed "prefix extension" fix.
NEVER: accept "candidate m only needs to share SOME single prime of a fixed set Q with the anchor a_1 (or with Q as a whole via H(Q)-membership)" as proof m is a legal/safe next term against ALL earlier constraints — different earlier terms can be covered by DIFFERENT primes of Q, so a candidate witnessing only one specific prime need not intersect every earlier term's covering prime; the only provably-safe construction is a multiple of the FULL PRODUCT prod(Q), not mere H(Q)-membership. This exact trap recurred three times in imo-2026-06 (jacobsthal-covering-bound's g(Q)-threshold, round 2; and bounded-link-invariant's baseline step b_n defined via "gcd(a_n+d,a_1)>1" then claimed "always a legal candidate," round 3) — always re-derive the safe bound from the certified bounded-gap-via-rad-a1 pattern (next multiple of rad/prod(Q)) before trusting a "covering membership" shortcut.
ALWAYS: distinguish two pigeonhole shapes when reviewing a "monotone finite-state stabilizes" claim — (a) SOUND: a set-valued sequence that is monotone non-decreasing (under ⊆) inside a universe fixed independently of n (e.g. jacobsthal-covering-bound's Λ_n ⊆ {p ≤ R}, R fixed by a_1) must stabilize, no specific-value recurrence needed; (b) UNSOUND: claiming a specific state (e.g. the n=1 state) recurs merely because the codomain is finite. Round 3's Λ-stabilization lemma is case (a) and is correctly sound — don't reflexively flag every pigeonhole as the round-2 fallacy; check which shape it actually is.
ALWAYS: when an outline proposes a "cheap numerical kill-check" to be run "first" by the builder, run it yourself during review if it's cheap (a few lines of python3+sympy) — round 4's jacobsthal-covering-bound proposed testing candidate Q:=Lambda as a hitting set "before any proof attempt"; running it immediately found (a) Lambda alone violates the population's own Q superset R(a_1) convention and fails trivially, and (b) even the corrected Lambda union Q_0 fails on one of the outline's own three named test instances (a_1=99, missing prime 5) — this saved a build cycle and let the builder start from a falsified/corrected premise instead of re-discovering it.
NEVER: treat "external classical theorem (e.g. Sperner) gives an upper bound on X" as progress toward a termination/existence proof unless the outline also states the missing converse/lower-bound direction explicitly and flags it as unresolved — round 4's active-set-stabilization Sperner argument did this correctly (upper bound only, converse explicitly flagged open, first-check-numerically instruction given), which is why it passed review as sound rather than as the counting-implies-termination fallacy killed in rounds 2-3.
ALWAYS: when a "per-term" statistic (e.g. rho(n):=|R(a_n) intersect Q| >= 2) is proposed to block a "per-pair" bad event (e.g. a pairwise intersection being a singleton), check whether the per-term property actually forces the per-pair property — it usually doesn't automatically (two elements each having 2 qualifying primes need not share 2 of the SAME primes). Name this gap explicitly even when the outline already marks the lemma "open" (round 5, imo-2026-06: active-set-stabilization's Redundancy Growth Lemma target rho(n)>=2 doesn't obviously imply state-compactness-pigeonhole's needed pairwise-multiplicity->=2 target).
ALWAYS: when two "advance" approaches in the same framing propose closely-related new sub-lemmas as this round's target (variations of one underlying idea), approve both individually if each is honestly gapped, but flag in the report that if both stall on the same idea this round, next round should retire the idea rather than reframe it a third time within the same population (round 5, imo-2026-06).
ALWAYS: use `copy_approach` (not `register_approach`) when the outliner's own report labels a new slug "copy-of <source>" — it inherits the source's Elo/counts so the fork starts as a true peer rather than a cold-start 1500 newcomer; confirmed correct semantics for a same-gap, independent-mechanism fork (round 6, imo-2026-06 scalar-difference-majorization copied from scalar-difference-pigeonhole).
ALWAYS: when an outline's own text already flags "this bound covers distinct SUMS/values, not necessarily distinct FACTORS/objects — needs a careful argument to fix" (a collision/injectivity gap self-admitted by the outliner), require the builder to resolve exactly that gap as a mandatory step 0, not fold it into a generic "open gaps" list — this is the same class of self-flagged-gap issue as rule 3, generalized beyond circularity to any counting-bound-vs-actual-target mismatch (round 6, imo-2026-06 scalar-difference-pigeonhole's Morse-Hedlund complexity-vs-sum-count gap).
ALWAYS: when an outline explicitly flags a broader case as "untested by the explorer, flag this as untested" while stating the theorem target in fully general form, run the cheap numeric check yourself on that exact flagged case before approving — round 7's imo-2026-06 renormalization-induction-on-seed stated "for every a_1 with min R(a_1)=3 and 5∤a_1, locks at L=3" but flagged >=3-prime seeds as untested; a direct simulation found a_1=429=3*11*13 (5 does not divide 429) breaks the lock, falsifying the general statement as written — this would have wasted a build cycle proving a false general theorem if the builder had extrapolated from only two-prime-seed numerics.
