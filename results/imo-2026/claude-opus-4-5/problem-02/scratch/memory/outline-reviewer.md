# Outline Reviewer Memory

## Round 1 Lessons

ALWAYS: Numerically verify claimed transformations (spiral similarities, maps) before approving an approach that relies on them (because spiral-similarity approach claimed B->N, K->C map that was numerically false, round 1)

ALWAYS: Check that angle conditions determine what is claimed - an angle equality alone does NOT determine a spiral similarity uniquely, only a family (because spiral-similarity approach confused angle condition with full transformation specification, round 1)

NEVER: Approve an approach whose skeleton relies on a false intermediate claim, even if the outline acknowledges uncertainty - send to RETHINK instead (because spiral-similarity had "naive guess is false" but proceeded anyway, round 1)

## Round 3 Lessons

ALWAYS: When an approach proposes a transformation (like inversion), verify that the transformed problem is actually EASIER - checking that inversion preserves angles at fixed points is not enough; must verify the non-fixed points (like M and N) transform to something tractable (because inversion-collinearity transforms M and N to circles, not points, making the Menelaus argument less clean, round 3)

ALWAYS: When multiple approaches converge to the same algebraic gap, rank transformation-based approaches higher than brute-force algebraic approaches (because transforming the problem structure often provides insight that pure symbolic manipulation misses, round 3)
